# bond-screen · 全市场纯债基金筛选

面向中国公募债券基金的纯债筛选技能与命令行工具。预制默认目标固定为 **400030 东方添益债券**，可临时指定其他目标；不包含个人持仓金额、加仓计划、固定候选名单或上次筛选结果。

> 一键执行的是“刷新市场数据 → 数值预筛 → 管理人报告核查 → 当前申购核查 → 筛选和导出”，不是联网模型自由猜测。公开数据源不可用或证据无法解析时，停止或列待核实，绝不拿旧结果假装最新。它不是交易工具，也不保证收益、数据源永远可用或穷尽所有无法核实的基金。

**适合**：按明确收益规则寻找值得进一步研究的纯债基金、比较指定目标、复核筛选依据。**不适合**：自动交易、保证收益、实时持仓监控，或仅凭近期排名直接买入。

可以独立运行，也可以安装为 Codex skill；**命令行完成取数与计算，模型只负责按本轮证据解释结果**。

## 快速开始

需要 **Python 3.10+、Git 和网络**。Linux 若缺少 `venv`，请先通过系统包管理器安装 `python3-venv`；Windows 需要可用的 `python` 命令。

启动器会自动创建虚拟环境，按 [requirements.txt](requirements.txt) 安装固定版本的 `requests`、`pypdf` 和跨平台时区库 `tzdata`。依赖未变化时不重复安装。**独立命令行运行无需基金账户、GitHub token 或模型 API key**；使用 Codex 本身的登录与访问要求另计。

### Linux / macOS

```bash
git clone https://github.com/yizhifendou1124/bond-screen.git
cd bond-screen
bash run.sh --output-dir ./bond-screen-results
```

后续沿用同一输出目录，默认以400030为目标，探测最新数据并增量补拉：

```bash
bash run.sh
bash run.sh --target-code 015736
bash run.sh --top-lists
bash run.sh --workers 2
bash run.sh --force-refresh
```

上述代码是不同用途的调用示例，不需要依次执行。`--target-code` 只影响本轮，不修改预制默认目标。

### Windows PowerShell

```powershell
git clone https://github.com/yizhifendou1124/bond-screen.git
cd bond-screen
powershell -File .\run.ps1 --output-dir .\bond-screen-results
powershell -File .\run.ps1 --target-code 015736 --top-lists
```

如果所在机器的策略禁止执行脚本，可不经启动器直接运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts\run_market.py --output-dir .\bond-screen-results
```

不要为了运行本项目永久降低系统执行策略。Windows 启动器尚需在 Windows 实际环境验证，提供入口不代表已经完成该平台实测。

第一次全市场执行可能需数十分钟或更久，取决于数千份额数据、管理人PDF及源站限流。默认6个并发，最大8；请求在同一主机间共享节流，遇到429/503/514会全局冷却、降低速率并尊重Retry-After，最多尝试5次。遇到限流建议 `--workers 2`，不要提高请求强度或绕过限制。

## 安装为 Codex skill

在自己的工作项目内安装，不要覆盖已有同名技能：

```bash
mkdir -p .agents/skills
git clone https://github.com/yizhifendou1124/bond-screen.git .agents/skills/bond-screen
```

在对应项目的 Codex 中使用；若技能列表未刷新，重新打开项目后再试：

```text
$bond-screen 筛选符合条件的纯债基金
$bond-screen 以015736为目标基金筛选
$bond-screen 生成今年、近半年、近3个月各最多5只
```

该技能运行同一套命令行流程；模型负责解释报告及待核实项，不能把未经核查的数据改成合格。安装入口为 [SKILL.md](SKILL.md)，实际发现目录以所用 Codex 版本的技能说明为准。

技能目录只读时，将运行环境与结果放在项目可写目录，也可不经模型直接运行：

```bash
BOND_SCREEN_VENV="$PWD/.bond-screen-venv" \
  bash .agents/skills/bond-screen/run.sh --output-dir "$PWD/bond-screen-results"
```

Windows 下的只读技能目录采用相同方式：

```powershell
$env:BOND_SCREEN_VENV = Join-Path $PWD ".bond-screen-venv"
powershell -File .\.agents\skills\bond-screen\run.ps1 --output-dir .\bond-screen-results
```

不要把结果或虚拟环境写进只读技能目录，也不需要复制作者机器的路径或缓存。更新已安装技能时，在项目根目录运行：

```bash
git -C .agents/skills/bond-screen pull --ff-only
```

独立克隆的仓库则在仓库内运行 `git pull --ff-only`。存在本地修改或分支分歧时先人工处理，不强制覆盖。

## 命令行参数

`run.sh` 与 `run.ps1` 将参数传给同一个在线入口 `scripts/run_market.py`。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `--target-code CODE` | `400030` | 本轮目标的六位基金代码，不持久化；缺数据不会自动换回默认 |
| `--output-dir PATH` | 当前目录下 `bond-screen-results` | 输出根目录；沿用同一路径以共享 `.cache/` |
| `--workers N` | `6` | 并发范围 `1–8`；限流时建议降到 `2` |
| `--timeout SECONDS` | `25` | HTTP 请求超时参数，允许 `1–120` 秒；不是整轮执行时限 |
| `--top-lists` | 关闭 | 从正式名单生成今年、近半年、近3个月各最多5只的独立榜单，可重合 |
| `--force-refresh` | 关闭 | 绕过源数据与 PDF 缓存，不改变筛选规则 |
| `--calendar-file PATH` | 内置日历 | 自定义交易所日历 JSON，包含 `source` 与 `holidays`；格式见 [内置日历](references/trading-calendar.json) |

查看完整帮助，不启动全市场取数：

```bash
bash run.sh --help
```

启动器首次运行 `--help` 也会准备虚拟环境与依赖。Linux / macOS 可用 `BOND_SCREEN_PYTHON` 指定创建环境的 Python 可执行文件；两类启动器均支持 `BOND_SCREEN_VENV` 指定环境目录。

自然语言请求可以表达额外参考、排除项等本轮要求，但**不要把这些能力误当作现有 CLI 参数**。高级输入字段与离线计算见 [数据与计算协议](references/data-contract.md)；离线助手不负责联网获取数据。

## 核心规则

### 检索范围与数据口径

- **从全市场开始**：每轮刷新债基目录、核对分页与去重，再筛选及核验；不拿预置名单、持仓或上轮结果限定候选。暂停申购及新增份额也先进入目录，之后分别核查。
- **只与本轮目标比较**：默认没有额外参考或排除名单，目标自身单列基准。只有本轮明确指定时才采用额外参考／排除项；多个目标分别比较，不拼成逐年最优基准。
- **统一近期收益截止日**：目标、候选与补全来源的今年／半年／三个月同日、同口径；执行日与实际净值日分开展示。目标落后市场时停止正式比较，周末不虚构当天净值。
- **完整年度复利年化**：三年和五年使用最近3／5个完整日历年度，计算为 `[(∏(1 + 年度收益率))^(1/n) − 1] × 100%`，乘积中的收益率使用小数形式。2026年分别对应2023—2025、2021—2025，**不是滚动近3／5年收益率**。今年是实际年初至今收益，不预测全年、不强行年化。
- **只补真正缺失的数据**：由已核实的同一基金其他份额补全，保留已有实际值，包括0%及负收益；不借用其他基金、不链式转借。逐项记录来源代码与年度／区间，并标注“同基金份额补全年化”，不冒充新份额的独立历史。

### 基础硬门槛

| 项目 | 入选条件 | 不能确认时 |
| --- | --- | --- |
| 纯债属性 | 官方合同／招募说明书与最新完整披露持仓核查通过；实际非纯债敞口及明确期内交易不放行 | 观察／待核实，不仅凭基金名称或平台分类认定 |
| 总规模 | 最新公开披露的**整只基金全份额总净资产 ≥1亿元人民币**，含等于门槛 | 观察／待核实；不以单份额规模、资产总值或份额数替代 |
| 当前可申购 | 当前核查渠道允许申购，或有正额度的限购；披露额度、渠道、核查日期和限制 | 观察／待核实；停购、封闭期、未开放或零额度剔除 |

在线流程采用天天基金渠道口径，并核对管理人公开业务公告；某渠道暂停不等于全市场停购。申购与赎回分开披露，最低持有期不自动等于无法申购。可购买性逐份额核查，不能借用同基金其他份额的交易状态。

合同允许非纯债品种但最新完整披露实际符合的基金，可以按“实际持仓纯债”条件核查；仅看前十大或期末零持仓不够，明确期内买入股票、普通可转债、可交换债等仍剔除。只称“最新披露持仓符合”，不声称报告日后实时持仓已知。缺少非决定性全期否定声明的处理见 [备注保留](#备注保留)。

**国债期货单独核查**合同许可、套保／利率与久期管理用途、品种及持仓，不与股指期货或权益敞口混判。用途或明细无法确认则待核实；不能仅凭交易事实剔除，也不能仅凭期末零仓位无条件放行。案例代码不是白名单。

### 收益硬剔除 R0–R4

以下 `C` 为候选，`T` 为本轮目标，`R` 为同一只有效参考（默认只有目标），`H` 为固定的2020—2025检查集合。差值均为**百分点**，按未四舍五入值判断，显示时再保留两位；历史相等只能称“不低于”。

| 规则 | 触发剔除的条件 | 边界与范围 |
| --- | --- | --- |
| R0 异常收益 | 某完整年度收益减去该基金**其他完整年度算术平均收益 ≥15.00个百分点**；或有已核实非经常性净值异常 | 平均值不含被检查年度；用2020年起已取得的全部完整年度，同基金其他份额触发时整只基金剔除；不等于“年收益超过15%” |
| R1 历年完全被压过 | `H` 中每年均有 `C年度 < R年度` | 某年相等不触发；完整见证须来自同一参考 |
| R2 今年落后且历史优势不足 | 同一 `R` 满足 `R今年 − C今年 ≥0.50`，且 `max(C年度 − R年度) ≤0.20` | 两个边界均包含；不能拼接不同参考的逐年优势 |
| R3 今年明显落后目标 | `T今年 − C今年 ≥2.00` | 只对本轮目标比较；长期年化领先也不豁免 |
| R4 完整年度非正收益 | 从2020年起至净值截止日前一年的任一完整年度收益 `≤0%` | 0%、-0%和负收益均剔除；实际正值显示为0.00%不因此剔除，缺失值不按0%处理 |

R1／R2的检查集合固定为2020—2025，不随三五年窗口擅自滚动；R0／R4从2020年起检查完整年度，2020年前不纳入。覆盖不足或异常疑点未核实则观察，不删除异常年后重算，也不换份额规避。目标异常或待核实会停止正式收益比较；目标规模、申购状态或非正年度不自动触发换目标。

### 通过硬门槛后的三类保留

| 顺序 | 分类 | 保留条件 |
| --- | --- | --- |
| ① | 两项年化均不低于目标 | 三年与五年分别都不低于目标 |
| ② | 一项年化不低于目标 | 仅一项不低于目标，披露另一项弱势；不额外套用0.30个百分点门槛 |
| ③ | 两项都低但满足近期例外 | `C今年 ≥ T今年 −0.30个百分点`，且 `H` 中至少一年不低于目标 |

**三类都必须先通过全部硬限制**。各类内部按未四舍五入的今年收益降序，同收益按代码升序；先完成同基金份额去重，不跨类混排、不硬凑数量。半年／三个月展示差值，不擅自增加相似门槛。

仅作边界演示：若目标今年收益为4.34%，R3会剔除今年收益≤2.34%的候选；两项年化都低的候选还须达到今年≥4.04%，并满足历史条件及其他硬门槛。**这些数值是假设示例，不是当前行情或推荐名单。**

完整定义以 [SKILL.md](SKILL.md)、[默认配置](references/defaults.json) 和 [数据与计算协议](references/data-contract.md) 为准。直接调用 `scripts/screen_funds.py INPUT.json` 只是离线计算，不表示联网完成全市场筛选。

## 结果与失败

输出到调用者当前目录的 `bond-screen-results/<时间戳>_market/`，也可用 `--output-dir` 指定：

|文件|内容|
|---|---|
|`report.md`|分类表、目标、日期、限购、待核实和覆盖风险|
|`retained_funds.csv` / `.json`|同基金去重后的正式名单，三类和今年降序一致|
|`screen_input.json` / `screen_output.json`|可复核输入、精确规则结果、补全与剔除见证|
|`coverage.json` / `market_audit.json`|目录数量、阶段预筛、未解决错误和覆盖缺口|
|`verification_issues.json` / `pending_funds.json`|报告核验问题与待核实份额，区分未取得、解析失败、收益冲突及持仓核查未完成|
|`cache_audit.json`|分层复用／更新／失败次数、每份额真实净值日、待补标签、原始抓取时间和哈希|
|`decision_audit.json`|规则／代码、规范化完整输入、结果哈希及上轮可比较性；同版本同输入不同结果阻止发布|
|`catalog.json` / `identities.json` / `annuals.json` / `fresh_funds.json`|本次目录、经缓存验证的身份及年度、请求状态和预筛数据；审计文件不作为下次候选名单|
|`family_reviews.json` / `source_manifest.json` / `evidence/`|报告依据、年度核对、公告及请求时间、原文和哈希|
|`failure.json`|关键失败或用户中断的诊断，不是成功结果|
|`top_lists.json`|仅 `--top-lists` 时输出三个近期榜单|

输出根目录的 `latest.json` 只在目标有效且本次导出完成后更新；关键失败时不回退读取它。退出码 `0`=完成，`3`=完成但有覆盖缺口，`2`=关键失败，`130`=中断。退出码3的正式名单仍通过硬门槛，但不能宣称全市场完全穷尽；检查覆盖文件。

| 退出码 | 含义 | 应如何处理 |
| --- | --- | --- |
| `0` | 本轮执行完成 | 读取本轮报告、净值截止日、覆盖及证据；不代表投资安全或未来收益有保证 |
| `3` | 已产出结果，但有覆盖／核验缺口 | 正式名单与待核实项分开使用，检查 `coverage.json`、`verification_issues.json`、`pending_funds.json` |
| `2` | 关键失败 | 查看本轮 `failure.json` 与 `source_manifest.json`，不要读取旧 `latest.json` 冒充本轮成功 |
| `130` | 用户中断 | 半成品不是正式结果；保留诊断，之后重新运行 |

Linux / macOS 可在命令结束后立即保存退出码：

```bash
bash run.sh --output-dir ./bond-screen-results
screen_status=$?
printf 'bond-screen exit code: %s\n' "$screen_status"
```

Windows PowerShell 使用 `$LASTEXITCODE`。自动化调用要单独识别退出码3，不把它误当作“完全没有产物”，也不自动改成0。首次依赖安装阶段出错时可能直接返回安装工具的退出码，尚未进入本轮筛选流程。

**阅读顺序**：先确认终端打印的本轮时间戳目录，再看 `report.md` 和 `coverage.json`；核验问题看 `verification_issues.json`／`pending_funds.json`；追溯资格看 `screen_output.json`、`decision_audit.json` 与 `source_manifest.json`。正式名单只采用本轮 `retained_funds.json`，不手工把观察项加进去。筛选数量为0不一定是故障，应区分硬剔除、待核实与关键失败。

HTTP成功不代表报告核验完成：已下载年报但未识别出对应份额收益，属于解析缺口，不是平台没有历史数据或业绩不合格。解析支持份额标题空格／换行、重复收益表、明确年度及份额的财务指标备选；风险提示不直接当作已发生异常。无法确认的项仍待核实，不为了增加数量放宽规则。

## 增量更新

沿用同一输出根目录可共享`.cache/`；第一次仍需完整取数。交易日每次探测批量排名，逐份额记录真实净值日与内容版本：周一已更新到共同截止日的完整详情不重复拉，尚未更新／缺失／失败的继续补查；目标与候选日期不能混用。同日收益修订也更新，不仅看日期。

周末及内置交易所日历覆盖的休市日，实时轻量核对目标日期及收益，未变则复用24小时内境内排名。周日最新净值为周五不触发全量历史重取；QDII排名每次独立刷新，不把境内休市当作海外未更新。内置日历覆盖2026年，来源见`references/trading-calendar.json`；其他年份工作日保守探测，可通过`--calendar-file`指定新的交易所日历。

身份、完整年度和同公告编号PDF最多缓存7天；PDF提取全文同时检查PDF／文本／解析器版本哈希。公告目录和当前申购状态每轮实时刷新，筛选结果每轮重算。过期、损坏、缺年、无法识别或影响资格的收益冲突、新公告等触发重取，旧请求失败不以旧值冒充成功。已记录双方数值且通过资格敏感性检查的备注差异，按原有效期复核，不每轮重下同一原件。运行`bash run.sh --force-refresh`可绕过所有复用。

轻量探测不保证即时发现每只基金的静默历史修订；缓存最长有效期及官方收益交叉核对控制风险，疑点仍待核实。详见 [缓存与更新策略](references/cache-policy.md)；审计中的复用时间不冒充原始下载时间。

## 结果一致性

相同规则／代码与完整输入必须给出相同资格结果。净值不变不代表申购、公告、补齐数据或核验状态没变；查看`decision_audit.json`再解释名单变化。正式名单和原因严格来自计算输出，模型不能临时追加筛选标准或把`observation`说成业绩硬剔除。发现判断错误须修复通用实现并保存重算副本；归档重放不是最新联网全市场结果，不能覆盖原证据或更新正式latest指针。

审计的`fund_decision_changes`逐基金记录前后状态、原因和核验问题，并分别标记基金输入与收益数据是否变化；没有旧指纹时标明无法比较。历史改名以官方原合同名称及份额代码核对，空交易章节和持有人赎回款不误读为真实投资，不用旧名单或手工标记恢复资格。

## 备注保留

核心持仓与交易记录已核查，仅缺合同许可品种的全期否定声明时，可以备注保留；明确非纯债交易、核心披露缺失仍不放行。可识别年度收益来源有差异时保留两个值，按上下界及年度异常最不利组合检验资格；不改变入选资格才备注保留，来源区间可能触及收益／非正收益／异常门槛时仍待核实，已有实际0%或负值直接剔除。0.02个百分点的数字对照容差不改，但不能跨越零收益边界放行，不覆盖原实际值。

备注基金仍在原三类内排序，表内标※，CSV新增`note_text`，JSON保留`disclosure_notes`、`retained_with_notes`、`return_source_sensitivity`及独立`disclosure_notes.json`。备注揭示不确定性，不是确认全期未交易、无风险或当前实时持仓。

## 常见问题

### 为什么正式名单较少，或退出码是3？

不一定是全市场只有这些基金合格。正式名单只是**本轮已完成核验**的结果；源文件未取得、已取得但字段未识别、收益冲突、实际持仓核查未完成都会留下缺口。先读具体诊断，再针对来源补查，不把“待核实”解释为“业绩不合格”，也不借用上轮入选结论放行。

### 为什么周末仍显示周五净值？

以实际最新披露净值日为准，周末没有当天净值通常正常；申购状态仍按本次当地核查日单独确认。不因日期不是执行日而要求补不存在的数据，也不把QDII套用境内休市日历。

### 为什么净值没变，名单却变了？

新公告、申购状态、历史数据补齐、核验状态或程序版本都可能改变资格。先对照 `decision_audit.json`；同版本、同完整输入出现不同资格结果是程序错误，应停止发布并修复，而不是归因于市场。

### 新增份额没有六年独立历史，还能参加吗？

可以先核实官方同基金关系，再补真正缺失的年度或同日区间。已有实际值不覆盖，可申购状态不借用，异常限制作用于整只基金。无法取得可靠补全来源时仍待核实；补全不能冒充该份额独立成立以来的业绩。

### 遇到限流、超时或 PDF 解析失败怎么办？

保留本轮输出与具体来源诊断，等待后以 `--workers 2` 重试同一输出目录。`--timeout` 只调整请求超时，`--force-refresh` 用于明确要求重抓或排查修订，并非限流的解决方法。已下载但无法识别的PDF属于解析缺口；需维护通用解析器或核实原文，不手改基金为合格、不绕过访问限制。

### 三个近期榜单是否等于三个独立筛选器？

不是。`--top-lists` 在正式合格名单内分别排序，今年、近半年和近3个月各最多5只，可以重合、可以不足5只；不会为了凑数放宽R0–R4或加入观察项。

### 命令行运行需要调用大模型吗？

不需要。取数、核查与规则计算由Python流程完成；Codex skill只是使用同一流程的交互入口。`scripts/screen_funds.py` 本身只计算已获取的输入，不联网、不交易，也不证明完成了一次全市场检索。

## 测试与维护

Linux / macOS，使用已经安装依赖的虚拟环境：

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/run_market.py --help
```

Windows 将 `.venv/bin/python` 替换为 `.\.venv\Scripts\python.exe`；使用 `BOND_SCREEN_VENV` 时采用相应环境中的Python。

仓库 CI 使用离线合成数据，不将实时第三方服务可用性当成确定通过的单元测试。真实全市场运行应检查报告日期、覆盖和目标有效性。数据页面/接口结构发生变化时会报错或观察，需要维护解析器，而不是放松硬门槛。

提交问题时请提供程序版本／提交号、完整执行参数、退出码、执行日与净值截止日，以及相关诊断文件中的最小片段。不要提交个人持仓、账户信息或访问凭证；公开行情快照及整份第三方PDF也不应默认上传。规则错误须修复通用实现、补充边界回归测试，并保留可追溯的重算副本，不按代码设白名单。

## 数据来源与风险

数据源为天天基金/东方财富公开页面与公开接口、管理人公开披露的完整报告PDF。接口不是本项目控制的稳定商业API，不承诺SLA；尊重源站服务条款和访问限制，不绕过认证、付费墙或限流。基金收益不含个人申赎费用，公开持仓有披露滞后；本工具不保本、不自动下单。

筛选通过仅表示值得进一步研究。还需复核回撤与修复、久期、信用质量、杠杆、经理和规模变化、持有人结构、费用及申赎限制；这些复核维度不是模型可随意新增的硬剔除阈值。历史业绩不保证未来收益，纯债不等于保本。按请求运行本工具不代表已设置定时任务、提醒或交易。
